## 项目简介

回声馆是一座能在浏览器里自由行走的 3D 展馆：一条回声走廊串起五间主题展厅——镜厅（画廊）、幕厅（影院）、书厅（书房）、乐厅（卧室与黑胶）和游厅（小游戏机柜）。访客以第一人称视角漫游，可以细看每一件展品、坐下听歌、躺下看星空、在机柜上玩一局扫雷。

原生 Three.js + Vite 实现，**没有引入任何前端框架**，全部逻辑为 vanilla ES Module。线上地址：[echo-hall-81378.app.workbuddy.host](https://echo-hall-81378.app.workbuddy.host/)。

下面按漫游顺序，用截图带大家走一遍这座馆。

## 回声走廊：馆的骨架

![回声走廊](/images/echo-hall/corridor.jpg)

走廊是整座馆的动线骨架：尽头一座落地钟压轴，两侧对称布置盆栽、长凳与侧墙小画，挂画与吊灯构成节奏感。这里也是空间规则最集中的地方——

- 走廊两侧各有三扇门，门槽位（`doorSlots`）是硬约束：任何家具的落点必须离最近门框留出「门框半宽 + 物件半宽 + 余量」。
- 成对装饰严格左右对称（两盆盆栽、两幅小画），冲突时优先挪单件家具，不动成对件——对称一旦破坏，视觉上立刻能察觉。

## 镜厅：程序化生成的画廊

![镜厅全景](/images/echo-hall/mirror-hall.jpg)

镜厅是画廊主题厅：中央一组金色扶手椅与茶几围合成休息区，四壁挂满画作。所有挂画——包括画框、画布纹理、展签——都是 **Canvas 程序化生成**的贴图，整座馆零图片资产依赖。

点击任意一幅画可以看大图、换展签，展品信息由展厅代码以数据形式声明。

## 书厅：书房与阅读 UI

![书厅全景](/images/echo-hall/paper-hall.jpg)

![书页阅读界面](/images/echo-hall/reading.jpg)

书厅是书房主题：书架顶天立地，书脊用 Canvas 随机生成色彩条纹，顶排挂画与书架顶盖严格错位。走近书桌点击摊开的书本，会进入上图的书页阅读界面——页面翻转、行距、页码都是 DOM 叠加层实现，与 3D 场景解耦。

## 幕厅：影院与放映

![幕厅全景](/images/echo-hall/screen-hall.jpg)

![银幕放映特写](/images/echo-hall/screen-video.jpg)

幕厅是影院主题：深红墙面配阶梯座位，吸音软包、碟墙与放映机俱全。碟墙挑片后碟片会飞进放映机，随后银幕亮起开始放映（放映特写见上图）。

## 乐厅：黑胶、卧室与银河

![乐厅唱机与频谱](/images/echo-hall/sound-hall.jpg)

乐厅是卧室与音乐主题：黑胶唱机带转盘动画与 VU 电平表，播放时柜面频谱随音乐起伏。床、毯凳、床头小几等家具来自共享道具库，床头几与毯凳之间留足了间隙——这类细缝就是占地审查的产出。

这间房最惊艳的交互在床上：点击「躺下看星空」，床头灯熄掉、壁灯与灯槽一起压暗，整个房间只剩头顶的天。乐厅没有天花板——是一片真实银河全景穹顶（4K 星图打底，再叠 7000 颗程序化生成的星点独立闪烁）。下图就是躺下后的仰视视角：

![躺下看银河](/images/echo-hall/galaxy.jpg)

## 游厅：机柜与扫雷

![游厅霓虹机柜](/images/echo-hall/arcade.jpg)

![机柜扫雷面板](/images/echo-hall/minesweeper.jpg)

游厅是游戏厅主题：霓虹灯管渲染出街机厅的氛围，几台机柜一字排开。走近机柜点击屏幕，进入上图所示的扫雷面板——这是把一个完整的 2D 小游戏嵌进 3D 场景的尝试，面板同样是 DOM 叠加层。

## 交互灯箱：一件展品的解剖

![《双生》交互灯箱](/images/echo-hall/lightbox.jpg)

这张图是单件展品的特写：一座名为《双生》的交互灯箱。它是全馆可交互展柜的缩影——每个展柜都有「走近出现提示 → 点击 → 反馈」的完整链路，交互圈心与半径在房间代码里显式声明，摆放新物件前先校验是否落在已有交互圈内，避免几个提示互相打架。

## 核心能力

### 五间展厅，一套生命周期

- 每间房都是一个独立模块（`src/rooms/*.js`），统一走「懒建 + LRU 淘汰 + dispose」的生命周期，进哪间建哪间，离开的房间自动释放显存。
- 房间内部使用局部坐标系（`spawn` / `bounds` / 物体坐标都是房间局部的），渲染时整体平移，改房间尺寸不用换算一堆世界坐标。

### 交互系统

- 数十处可交互对象统一走「圈内 + 在身前 + 由近到远打分」的 proximity 判定，始终聚焦离你最近的那一件。
- 点击展柜看大图、碟墙挑片飞进放映机、唱机转盘与电平表、躺下看星空——反馈全部所见即所得。

### 道具系统：程序化几何 + GLB 双通道

- 13 个道具工厂函数（长凳、落地灯、边桌、盆栽、挂钟、扶手椅、毯凳……）构成 `furnishing.js` 道具库，五间房共用。
- 所有程序化件内置 `glb` 钩子：把模型文件丢进约定目录即自动顶替，位置、朝向、归一化尺寸不用改代码；模型缺失或加载超时自动回退程序化件，位子永远有东西站着。
- 贴图层面用 Canvas 程序化生成（挂画、海报、展签、唱片区封面），零图片资产依赖。

## 设计要点

**房间用局部坐标系，而不是世界坐标。** 六间房（含走廊）尺寸各不相同，如果所有家具都按世界坐标摆，改一间房的尺寸就要重算房里每件东西。把每间房的物体坐标都定义在房间局部系里、渲染时整体平移，房间成了可插拔的模块，尺寸调整只影响房间自己。

**交互用「圈内 + 身前 + 由近到远」打分，而不是射线拾取。** 展品大多贴在墙上或摆在桌上，射线拾取对第一人称视角太苛刻——得把准心对准。改成「进入交互圈 + 在身体前方 + 按距离打分」后，走近就能看到提示，视线随意也能点中；同时交互圈半径写进房间数据，摆新物件时能提前判断会不会跟已有交互抢焦点。

**程序化几何优先，GLB 作为可选升级。** 展馆里几百件家具如果全用模型，初次加载会很重；全用代码生成又显粗糙。做法是每个道具工厂都先程序化建出完整形态，并预留 `glb` 钩子——有模型就替换、没有就用程序化件，加载超时也回退。这样开发期不依赖任何美术资产，后期逐步替换成模型也不用改一行摆放代码。

**落位前先做占地相交测试。** 家具穿模在 3D 场景里非常显眼，靠眼睛逐个房间检查不可靠。把每件落地物的占地记成 2D 盒子，两两做相交测试，走廊再叠加门槽位这条硬约束，落位是否合法就变成了一道可以算的题。

## 技术栈

| 层 | 技术 |
|---|---|
| 渲染 | Three.js 0.186，ACESFilmicToneMapping，光晕用加法混合面片 |
| 模型 | GLB 归一化（单轴给尺寸、等比缩放、底面落地、水平居中）+ FBX 第一人称手臂 |
| 贴图 | PBR 材质工厂 + Canvas 程序化贴图，长边 512 封顶 |
| 交互 | 自研 proximity 判定（圈内 + 身前 + 距离打分）+ DOM 叠加层 UI |
| 构建 | Vite 8（vanilla ES Module，无框架） |
| 性能 | 房间懒加载 + LRU、阴影灯数量克制、纹理 anisotropy 自适应 |
