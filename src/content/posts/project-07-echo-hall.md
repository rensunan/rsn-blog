## 项目简介

回声馆是一座能在浏览器里自由行走的 3D 展馆：一条回声走廊串起五间主题展厅——镜厅（画廊）、幕厅（影院）、书厅（书房）、乐厅（卧室与黑胶）和游厅（小游戏机柜）。访客以第一人称视角漫游，可以细看每一件展品、坐下听歌、躺下看星空、在机柜上玩一局扫雷。

原生 Three.js + Vite 实现，**没有引入任何前端框架**，全部逻辑为 vanilla ES Module。线上地址：[echo-hall-81378.app.workbuddy.host](https://echo-hall-81378.app.workbuddy.host/)。

下面按漫游顺序，用截图带大家走一遍这座馆。

## 回声走廊：馆的骨架

![回声走廊](/images/echo-hall/corridor.jpg)

走廊是整座馆的动线骨架：尽头一座落地钟压轴，两侧对称布置盆栽、长凳与侧墙小画，挂画与吊灯构成节奏感。这里也是所有「空间纪律」的主战场——

- 走廊两侧各有三扇门，门槽位（`doorSlots`）是硬约束：任何家具的落点必须离最近门框留出「门框半宽 + 物件半宽 + 余量」，否则就会穿门。
- 成对装饰强制左右对称（比如两盆盆栽、两幅小画），发现冲突时优先挪单件家具，不动成对件——对称一旦破坏，视觉上立刻能察觉。

## 镜厅：程序化生成的画廊

![镜厅全景](/images/echo-hall/mirror-hall.jpg)

镜厅是画廊主题厅：中央一组金色扶手椅与茶几围合成休息区，四壁挂满画作。所有挂画——包括画框、画布纹理、展签——都是 **Canvas 程序化生成**的贴图，整座馆零图片资产依赖。

点击任意一幅画可以看大图、换展签，展品信息由展厅代码以数据形式声明。

## 书厅：书房与阅读 UI

![书厅全景](/images/echo-hall/paper-hall.jpg)

![书页阅读界面](/images/echo-hall/reading.jpg)

书厅是书房主题：书架顶天立地，书脊用 Canvas 随机生成色彩条纹，顶排挂画与书架顶盖严格错位。走近书桌点击摊开的书本，会进入上图的书页阅读界面——页面翻转、行距、页码都是 DOM 叠加层实现，与 3D 场景解耦。

## 幕厅：影院与星空

![幕厅全景](/images/echo-hall/screen-hall.jpg)

![银幕放映特写](/images/echo-hall/screen-video.jpg)

![躺下看银河](/images/echo-hall/galaxy.jpg)

幕厅是影院主题：阶梯座位、吸音软包、碟墙与放映机俱全。碟墙挑片后碟片会飞进放映机，随后银幕亮起（放映特写见上图）。

这间房最好玩的交互是「躺下」：走到座位区按下交互键，视角放平、灯光熄灭，天花板变成星空穹顶——第三张图就是躺着看到的银河。星空用加法混合面片冒充光晕，没有上 bloom 后处理，性能友好。

## 乐厅：黑胶与卧室

![乐厅唱机与频谱](/images/echo-hall/sound-hall.jpg)

乐厅是卧室与音乐主题：黑胶唱机带转盘动画与 VU 电平表，播放时柜面频谱随音乐起伏。床、毯凳、床头小几等家具来自共享道具库，床头几与毯凳之间留足了间隙——这类细缝就是占地碰撞审查的产出。

## 游厅：机柜与扫雷

![游厅霓虹机柜](/images/echo-hall/arcade.jpg)

![机柜扫雷面板](/images/echo-hall/minesweeper.jpg)

游厅是游戏厅主题：霓虹灯管渲染出街机厅的氛围，几台机柜一字排开。走近机柜点击屏幕，进入上图所示的扫雷面板——这是把一个完整的 2D 小游戏嵌进 3D 场景的尝试，面板同样是 DOM 叠加层。

## 交互灯箱：一件展品的解剖

![《双生》交互灯箱](/images/echo-hall/lightbox.jpg)

这张图是单件展品的特写：一座名为《双生》的交互灯箱。它是全馆 40 座可交互展柜的缩影——每个展柜都有「圈内聚焦提示 → 点击 → 反馈」的完整链路，交互圈心与半径在房间代码里显式声明，摆放新物件前先校验是否落在已有交互圈内，避免抢走主件的聚焦。

## 核心能力

### 五间展厅，一套生命周期

- 每间房都是一个独立模块（`src/rooms/*.js`），统一走「懒建 + LRU 淘汰 + dispose」的生命周期，进哪间建哪间，离开的房间自动释放显存。
- 房间内部使用局部坐标系（`spawn` / `bounds` / 物体坐标都是房间局部的），渲染时整体平移，改房间尺寸不用换算一堆世界坐标。

### 交互系统

- 39 处可交互对象统一走「圈内 + 在身前 + 由近到远打分」的 proximity 判定，圈内多件会抢焦点，所以新物件落位前必查交互圈。
- 点击展柜看大图、碟墙挑片飞进放映机、唱机转盘与电平表、躺下看星空——交互反馈全部所见即所得。

### 道具系统：程序化几何 + GLB 双通道

- 13 个道具工厂函数（长凳、落地灯、边桌、盆栽、挂钟、扶手椅、毯凳……）构成 `furnishing.js` 道具库，五间房共用。
- 所有程序化件内置 `glb` 钩子：把模型文件丢进约定目录即自动顶替，位置、朝向、归一化尺寸不用改代码；模型缺失或加载超时自动回退程序化件，**永远不会出现两件重叠或空位**。
- 贴图层面用 Canvas 程序化生成（挂画、海报、展签、唱片区封面），零图片资产依赖。

### 布局即数据

- 每件落地物都有占地记录，两两做 2D 盒子相交测试，杜绝组件穿模——本文截图里的每一处家具间隙都是这套审查的结果。
- 走廊门槽位导出为硬约束，成对装饰强制左右对称。

## 技术要点

| 项 | 方案 |
|------|------|
| 渲染 | Three.js 0.186，ACESFilmicToneMapping，无 bloom 后处理（光晕用加法混合面片冒充） |
| 模型 | GLB 归一化（单轴给尺寸、等比缩放、底面落地、水平居中）+ FBX 第一人称手臂 |
| 贴图 | PBR 材质工厂 + Canvas 程序化贴图，长边 512 封顶 |
| 性能 | 房间懒加载 + LRU、阴影灯数量克制、纹理 anisotropy 自适应 |

## 一个坑

Vite 默认 `emptyOutDir: true`，但这个项目把它关了——结果是 `dist/assets` 每构建一次就多攒一套 hash 包，积累到 74MB。发布工具按目录整包上传，陈旧产物把上传拖到超时。解决办法：构建后只保留 `index.html` 实际引用的三个 hash 文件（入口 JS、CSS、动态分包），其余全清，体积立减一半。
